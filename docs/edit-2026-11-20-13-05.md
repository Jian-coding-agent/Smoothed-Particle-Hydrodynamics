# 2026-11-20 13:05 — the follow-up review: C16–C20, P15–P17, M9

Machine: KMG-XI, 8 × RTX 5090 D (`sm_120`), CUDA 13.5, MSVC 19.29, CMake 4.4.5 + Ninja.
Every timing below is fp64.  **The box was running another project's 1 895-scenario HLLC
sweep (24 workers, three per GPU) for the whole session**, so the absolute numbers are
inflated by roughly 3× and only same-window ratios are meaningful here.

This covers [the follow-up review](../review/Claude/REVIEW-2026-11-19-d1-followup.md):
C16–C20, P15–P17, M9.  P18 (per-particle slack) and P12 (overlap) were not attempted, and
the L4/L5 calibration of the auto-K model is left open — the reasons are at the end.

## 1. Correctness

| id | what was wrong | fix |
|---|---|---|
| **C16** | `build_solid_lists()` returned early (`width <= 0`, no A3 pair) *before* the collective A6 hook, so that rank walked past two barriers and every later barrier paired out of phase: `inf` displacement, rebuild from garbage, hang | the A6 decision now happens before every early return, and the empty-list path allocates `sCnt` so the static kernels can run with zero partners |
| **C17** | repartition re-cut with solid weight 0.5 while start-up used 0.45, and `make_part` identified solids by comparing the weight | one weight (`g_w_solid`) everywhere, and `Deck::solid` carries the type explicitly |
| **C18** | the scheduled displacement check could overshoot `s/2` by up to 10 % of the skin, and the detecting step still ran on the old halo | P17 makes the check exact every step; the trigger now sits `2·MaxV·dt` below `s/2` |
| **C19** | `npair > 0` chose static vs cell-walk solid kernels *per rank*, so a rank with no pair ran a different (non-bit-identical) path than the single GPU | the choice is global; the static kernels run over an empty list |
| **C20** | `J.outStage` written by every rank | derived from the result index, so nothing is shared |

Verified on the review's degenerate deck (`make_decks.py lone` equivalent: one solid moved
0.41 m out of the lattice):

| run | before | now |
|---|---|---|
| lone deck, K=2, 501 steps | hang (killed after 60 s in the review) | completes, **byte-identical to K=1** |
| lone deck, K=1 | completes | completes, unchanged |

## 2. Performance

### P15 — the cell scan (★, the V2 regression)

V2 gives every rank the *global* grid, and `k_cell_scan` was a single 512-thread block, so
each rank scanned every cell of the domain every step.  Replaced with
`cub::DeviceScan::ExclusiveSum` + one device-to-device copy to re-arm the cursor.  It is an
integer scan, so the cell lists, the summation order and V2's byte identity are unchanged
(the K=1 file is still byte-identical to the previous build, which is the check that
matters).

CUB needs `/Zc:preprocessor` with MSVC 2019; that flag was added to both language paths in
`CMakeLists.txt`.

### P16 — a halo refresh is not a repartition (★, the 19.3 M regression)

A skin-triggered refresh now keeps the ownership map and only re-derives each rank's box
from its own live particles, then re-selects the ghosts.  The three whole-deck sorts, the
re-cut search and the entire deck copy are skipped (`SPH_D1_REPART` / `SPH_D1_REGRID` still
walk the full path).  `build_ranks()` takes the live positions as a parameter, so the
"copy the deck and overwrite x" step the C10 fix needed is gone as well — that copy was
2.2 GB at 19.3 M.

Measured at 237k / K=8, one event per step, same window (so the ~3× machine inflation
cancels):

| event | ms |
|---|---:|
| halo refresh (ownership kept) | **150–158** |
| full repartition (re-cut) | 255–260 |

That is −42 %, and it matches the review's breakdown: the sorts (315 ms of 912 at 1.9 M),
the re-cut and the deck copy were most of the cost.  At the review's measured ~205-step
interval late in a run this is 0.3 ms/step instead of 0.52 ms/step on a ~2.3 ms step.

What is *not* done: the remaining ~150 ms is the per-rank state rebuild (free every array,
re-allocate, re-upload, `cudaHostAlloc` per event) — the review's items 3/4 (capacity-sized
arrays, gid-space A3 lists).  That is the part that still scales with N, so 19.3 M is
better but not solved.

### P17 — an exact displacement check every step, free

The reduce now writes into the tail of the E1 staging block, so the value is copied to the
host and relayed with the records; each rank reads the peers' values from their send
blocks after the barrier.  No extra copy, no extra sync, no rate extrapolation — and C18
disappears with it.

## 4. Documentation (M9)

* `cuda/README.md`: "exchanged twice per step" → once, with what E1 carries and why E2 is
  gone; "the reduce runs every step" → it now *does* run every step, exactly, in the E1
  block; the P16 refresh and the `MaxV·dt` trigger are described.
* The validation section now says that comparing against `1.cpp` on a deck that reaches
  `z = 1` needs `SPH_REFLECT=flip`, because M8's default differs from the reference.
* The step-time summary lines report **wall clock** (P19), plus the rebuild count and the
  total rebuild time, and the per-rank line no longer hides them.

## 5. Not done

* **P18** (per-particle slack): the trigger still rebuilds on the largest displacement of
  any particle, not on motion that can actually reach a rank boundary.  With P16 the event
  is cheaper and with P17 the decision is exact, so the payoff shrank; it remains the next
  cheap win.
* **L4/L5** (auto-K calibration): the model is still in load units with a floor that is
  ~18× too small (L4) and the probe still measures on-card bandwidth rather than PCIe, and
  still leaves a context on every card (L5).  Calibrating it properly needs a timing
  harness on an idle box, which this session did not have.
* **P12** (overlap): unchanged — one exchange point left, and every kernel reads ghost `x`,
  so it needs the interior/boundary split.
* **A performance matrix** at 237k / 1203k / 9.6 M / 19.3 M on an idle machine, for
  K = 1, 2, 4, 8, plus the auto-K calibration.
